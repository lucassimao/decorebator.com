# Testing Guide - Updated with Version Alignment

This guide explains how to run tests locally with the same tools and versions used in the GitHub CI workflow.

## 🚀 Quick Start

### First-time Setup
```bash
# Install all development tools with correct versions
make setup

# Check that everything is installed correctly
make check-versions
```

### Run Tests

**For quick unit tests with beautiful output:**
```bash
make test-report
```

**For comprehensive testing (unit + integration):**
```bash
# Option 1: Using test script (recommended)
./scripts/run-tests.sh all

# Option 2: Using test script with enhanced reporting
./scripts/run-tests.sh report

# Option 3: Using make (traditional)
make test-integration
```

## 📊 Available Commands

### Makefile Commands
| Command | Description |
|---------|-------------|
| `make setup` | Install all tools matching GitHub workflow versions |
| `make check-versions` | Compare installed vs expected tool versions |
| `make test-report` | Run unit tests with structured output |
| `make test-report-full` | Run all tests using test script |
| `make test-ci` | Generate JUnit XML reports like CI |
| `make security-scan` | Run security scans (nancy + govulncheck) |
| `make test-unit` | Quick unit tests |
| `make test-integration` | Integration tests (requires Docker) |

### Test Script Commands
| Command | Description |
|---------|-------------|
| `./scripts/run-tests.sh setup` | First-time environment setup |
| `./scripts/run-tests.sh unit` | Unit tests only |
| `./scripts/run-tests.sh integration` | Integration tests only |
| `./scripts/run-tests.sh all` | All tests with proper setup |
| `./scripts/run-tests.sh report` | Comprehensive test report |
| `./scripts/run-tests.sh watch` | Watch mode (auto-reload) |
| `./scripts/run-tests.sh versions` | Check tool versions |
| `./scripts/run-tests.sh security` | Security scans |
| `./scripts/run-tests.sh clean` | Cleanup test environment |

## 🔍 Troubleshooting

### Common Issues

**"gotestsum not found"**
```bash
# Install with correct version
make setup
# or manually
go install gotest.tools/gotestsum@latest
```

**"Database configuration missing"**
```bash
# Make sure you're using the test script for integration tests
./scripts/run-tests.sh integration
# NOT: go test ./tests/integration/...
```

**"Docker services not running"**
```bash
# Clean up and restart
./scripts/run-tests.sh clean
./scripts/run-tests.sh setup
```

**Version mismatches**
```bash
# Check what's installed vs expected
make check-versions
./scripts/run-tests.sh versions

# Reinstall with correct versions
make setup
```

## 📈 Understanding Test Output

### gotestsum Formats
- **testname**: Shows test names as they run
- **short**: Minimal output
- **standard**: Traditional go test output

### Coverage Reports
- **Unit tests**: Target 70%+
- **Integration tests**: Target 80%+
- HTML reports: `make coverage-html`

### JUnit XML Output
Generated by `make test-ci` for CI integration:
- `unit-tests.xml`
- `integration-tests.xml`

## 🛡️ Security Scanning

Run the same security checks as CI:
```bash
# Using make
make security-scan

# Using script
./scripts/run-tests.sh security
```

Includes:
- **nancy**: Dependency vulnerability scanning
- **govulncheck**: Go-specific vulnerability checking

## 🔄 Continuous Testing

For development with auto-reload:
```bash
# Watch mode (unit tests only)
./scripts/run-tests.sh watch

# Manual watch with make
make test-watch
```

## 📝 Best Practices

1. **Always run `make setup` first** - Ensures correct tool versions
2. **Use `make test-report` for quick feedback** - Fast unit tests with nice output
3. **Use `./scripts/run-tests.sh all` for comprehensive testing** - Full CI-like experience
4. **Check versions regularly** - `make check-versions` after tool updates
5. **Clean up after failures** - `./scripts/run-tests.sh clean` if tests hang

## 🔗 Integration with CI

These commands produce the same output as GitHub Actions:
- `make test-ci` → Unit tests with JUnit XML
- `./scripts/run-tests.sh all` → Full test suite
- `make security-scan` → Security scanning

All tools and versions match the GitHub workflow exactly! 🎯
